# Visual E2E Proof

사용자 가시 결과물은 코드, 테스트, 빌드 성공만으로 완료되지 않는다. **최종 사용자 표면에서 캡처 → 이미지 자체 검증 → 채팅 표시 → OS 미리보기 표시**까지 수행한다.

## 완료 게이트

다음 네 조건을 모두 충족해야 시각 검증 완료를 선언할 수 있다.

1. **실제 결과물 캡처**: 소스나 내부 컴포넌트가 아니라 사용자가 접하는 실행·렌더링 환경에서 캡처한다.
2. **에이전트 자체 검증**: 이미지 열람 도구로 캡처를 직접 확인한다.
3. **채팅 인라인 표시**: 검증된 이미지를 절대경로 Markdown 이미지로 최종 응답에 표시한다.
4. **OS 미리보기 표시**: 같은 증거 이미지를 운영체제의 기본 이미지 뷰어로 연다.

파일 경로 링크만 제공하거나, 채팅과 OS 미리보기 중 한쪽에만 표시하면 미완료다. 작업 트리가 깨끗하거나 변경이 이미 커밋·병합된 경우에도 이번 작업에 사용자 가시 결과물이 있으면 이 게이트를 적용한다.

순수 백엔드 로직처럼 시각 결과물이 전혀 없는 작업에는 억지로 스크린샷을 만들지 않는다. 다만 사용자 가시 결과물이 있는데 실행 환경, 권한 또는 필수 데이터가 없어 캡처할 수 없다면 해당 제약을 정확히 보고하고 시각 검증 완료를 선언하지 않는다.

## 결과물의 실제 경계 선택

캡처 전에 시각 수용 기준과 사용자가 실제로 보는 표면을 식별한다.

- **웹**: 실제 브라우저에서 렌더링된 페이지. [references/web.md](references/web.md)를 읽는다.
- **모바일·데스크톱·게임·터미널 UI**: 실제 앱 창, 기기, 에뮬레이터 또는 시뮬레이터. [references/apps.md](references/apps.md)를 읽는다.
- **문서·PDF·슬라이드·스프레드시트·정적 디자인**: 편집 소스가 아니라 최종 렌더링 또는 내보낸 자산. [references/rendered-artifacts.md](references/rendered-artifacts.md)를 읽는다.
- **Godot 프로젝트**: 앱 지침과 함께 [references/godot.md](references/godot.md)를 읽는다.

프로젝트에 이미 신뢰할 수 있는 E2E 도구, 캡처 하네스 또는 실행 스크립트가 있으면 우선 사용한다. 단, 편의를 위해 실제 사용자 표면을 컴포넌트 단독 렌더나 내부 테스트 출력으로 바꾸지 않는다. 컴포넌트 탐색기 자체가 납품 결과물인 경우에만 그것을 최종 표면으로 인정한다.

## 캡처

1. 각 시각 수용 기준을 증명할 화면 상태를 정한다.
2. 결과물을 실행하거나 렌더링하고 데이터, 인증, 뷰포트와 상태를 재현한다.
3. 로딩과 애니메이션이 안정되고 필수 자산이 표시된 뒤 캡처한다.
4. 프로젝트 내부의 gitignore된 증거 디렉터리를 우선 사용한다. 없다면 워크스페이스 내부의 안정적인 출력 디렉터리를 사용한다.
5. 한 장이 여러 기준을 명확히 증명할 수 있으면 재사용한다. 전환이나 상호작용이 요구사항이면 전후 또는 핵심 상태를 각각 캡처한다.

캡처에는 테스트 데이터만 사용하고, 토큰·개인정보·내부 URL 등 불필요한 민감 정보가 들어가지 않게 한다. 실제 앱 상태나 사용자 데이터를 건드리는 실행은 먼저 백업하거나 격리한다.

## 자체 검증

사용자에게 보여주기 전에 모든 증거 이미지를 이미지 열람 도구로 직접 연다. 다음 중 하나라도 해당하면 고친 뒤 다시 캡처한다.

- 빈 화면, 단색 화면, 로딩 중 또는 크래시 화면
- 잘못된 페이지·창·사용자 상태
- 요구된 텍스트, 컨트롤, 데이터 또는 상태가 보이지 않음
- 잘림, 겹침, 오버플로, 깨진 폰트·아이콘·이미지
- 개발자 도구, 디버그 오버레이, 다른 앱 또는 민감 정보가 불필요하게 노출됨
- 변경 전 화면이나 캐시된 오래된 결과

파일 존재 여부나 이미지 크기 검사만으로 자체 검증을 대체하지 않는다.

## 두 곳에 표시

자체 검증을 통과한 동일 이미지를 모두 표시한다.

### 채팅

최종 응답에 절대경로를 사용한다.

```markdown
![검증한 화면 설명](/absolute/path/to/proof.png)
```

### OS 미리보기 앱

운영체제에 맞는 기본 뷰어로 증거 파일을 연다.

- macOS: `open "/absolute/path/to/proof.png"`
- Windows PowerShell: `Start-Process -FilePath "C:\absolute\path\to\proof.png"`
- Linux 데스크톱: `xdg-open "/absolute/path/to/proof.png"` 또는 환경에서 제공하는 동등한 기본 뷰어

여러 이미지가 있으면 한 번에 모두 열거나, 뷰어가 묶음 열기를 지원하지 않을 때 각각 연다. 명령 성공 여부를 확인한다. GUI 세션이나 뷰어가 없어 열 수 없으면 그 사실을 보고하고 OS 미리보기 완료를 주장하지 않는다.

## 완료 보고

최종 응답에 다음을 포함한다.

- 시각 수용 기준과 증거 이미지의 대응 관계
- 검증된 이미지의 인라인 표시
- 캡처를 재현할 수 있는 명령 또는 짧은 절차
- OS 미리보기 앱으로 연 결과

이미지는 요구사항을 증명하는 데 필요한 만큼만 사용하되, 중요한 상태를 개수 제한 때문에 생략하지 않는다.
