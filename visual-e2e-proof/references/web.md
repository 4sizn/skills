# 웹 결과물 캡처

웹 UI는 실제 브라우저의 최종 렌더링을 증거로 삼는다.

## 캡처 환경

- 프로젝트가 지원하는 브라우저와 대표 뷰포트를 사용한다.
- 기존 브라우저 E2E 도구나 로그인된 브라우저 세션이 작업 범위에 있으면 우선 활용한다.
- 페이지의 폰트, 이미지, 비동기 데이터와 지연 로딩이 끝난 뒤 캡처한다.
- 테스트용 데이터와 계정을 사용한다. 민감한 사용자 데이터가 보이는 세션을 증거로 남기지 않는다.

## 화면 단위

- 상호작용, 모달, 메뉴, 오류, 반응형 레이아웃은 해당 상태가 보이는 **현재 뷰포트**를 캡처한다.
- 페이지 전체 구성이나 긴 문서 흐름이 요구사항일 때만 전체 페이지 캡처를 사용한다.
- 반응형 동작이 요구사항이면 관련 breakpoint 양쪽을 각각 캡처한다.
- 인증, 라우팅 또는 데이터 연동이 결과의 일부라면 실제 앱 흐름을 거쳐 최종 페이지를 캡처한다.

컴포넌트 하네스나 Storybook은 그것 자체가 납품 대상이거나 사용자가 명시적으로 컴포넌트 단위 증거를 요청한 경우에만 최종 증거로 사용한다. 애플리케이션 변경은 애플리케이션 페이지에서 증명한다.

## 확인 항목

- 올바른 URL, 페이지 제목과 사용자 상태
- 요구된 내용과 인터랙션 상태
- 뷰포트 안의 잘림, 가로 스크롤, 고정 요소 겹침
- 깨진 자산, 대체 폰트, 로딩 placeholder 또는 개발 오버레이 부재
