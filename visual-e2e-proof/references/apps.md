# 애플리케이션 결과물 캡처

모바일, 데스크톱, 게임과 터미널 UI는 사용자가 실행하는 애플리케이션 단위에서 증명한다.

## 실행 표면 선택

- 모바일: 실제 기기를 우선하되 요구사항을 충실히 재현할 수 있으면 에뮬레이터·시뮬레이터도 사용할 수 있다. 기기 고유 동작이 핵심이면 실제 기기를 사용한다.
- 데스크톱: 빌드되거나 개발 모드로 실행 중인 실제 앱 창을 캡처한다.
- 게임: 실제 게임 뷰포트에서 요구된 장면과 상태를 캡처한다.
- 터미널 UI: 일반 로그 텍스트가 아니라 사용자가 조작하는 실제 터미널 UI 화면을 캡처한다.

앱 변경을 단독 컴포넌트, 내부 디버그 패널 또는 테스트 스냅샷만으로 증명하지 않는다. 하네스로 상태를 준비해도 최종 캡처는 실제 애플리케이션 표면이어야 한다.

## 상태 재현

- 앱을 요구사항과 같은 진입점에서 시작하고 필요한 탐색과 상호작용을 수행한다.
- 애니메이션이나 비동기 상태가 핵심이면 의미 있는 전후 또는 핵심 단계들을 각각 캡처한다.
- 상태 표시줄, 시스템 권한 창, 키보드, 창 크기와 배율이 결과에 영향을 주면 재현 조건을 기록한다.
- 앱의 기존 사용자 데이터나 저장 상태에 닿는 하네스는 격리된 프로필을 쓰거나 실행 전 백업하고 실행 후 복원한다.

## 확인 항목

- 캡처 대상 앱과 화면이 맞는지
- 요구된 상태, 제어 요소와 콘텐츠가 실제로 보이는지
- 안전 영역, 키보드, 창 테두리와 배율에서 잘리거나 겹치지 않는지
- 크래시 대화상자, 디버그 UI, 다른 앱과 민감 정보가 노출되지 않는지
