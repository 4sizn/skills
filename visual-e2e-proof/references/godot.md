# Godot 결과물 캡처

Godot 프로젝트에서는 요구사항에 맞는 가장 재현 가능한 캡처 방식을 선택하고, 최종 증거는 실제 게임 또는 앱 뷰포트에서 얻는다.

## 캡처 방식

1. **결정적 인엔진 캡처**: 실제 씬을 인스턴스화하고 입력 신호나 상태를 재현한 뒤, 렌더 프레임이 안정되면 viewport texture를 PNG로 저장한다. 인터랙션, 모달, 전환과 애니메이션 상태에 적합하다.
2. **재사용 가능한 스크린샷 하네스**: 씬, 해상도와 출력 경로를 인자로 받아 정적 레이아웃이나 해상도 매트릭스를 캡처한다.
3. **라이브 창 캡처**: 실행 중인 실제 세션 상태 자체가 증거여야 할 때 운영체제의 창 캡처 수단을 사용한다.

프로젝트에 기존 캡처 스크립트가 있으면 그 계약과 출력 경로를 따른다. 없다면 일회성 도구를 프로젝트의 임시 또는 gitignore된 증거 영역에 둔다.

## Godot 주의사항

- 렌더링이 필요한 캡처를 더미 렌더러 기반 headless 실행으로 만들지 않는다. 사용할 Godot 버전과 플랫폼에서 실제 렌더링이 가능한 실행 모드를 선택한다.
- 씬 진입 직후가 아니라 레이아웃, 폰트, 셰이더와 애니메이션이 안정되도록 필요한 프레임을 기다린다.
- 저장 전 viewport image가 유효하고, 저장 후에는 이미지 자체를 열어 블랭크 여부와 요구 상태를 확인한다.
- 실제 launcher나 저장 시스템이 사용자 데이터에 닿으면 격리된 사용자 디렉터리를 쓰거나 데이터를 백업·복원한다.
- 하네스가 상태를 직접 주입해도 최종 화면은 제품 씬과 동일한 렌더 경로를 사용해야 한다.
