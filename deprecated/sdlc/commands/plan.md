# /sdlc:plan — SDLC 프로젝트 계획

`$ARGUMENTS`

## 0. 규약 로드

`sdlc-waterfall` 스킬을 Skill 도구로 로드한다.

## 1. 게이트

**`requirements.md` · `status: approved`**

미통과 시 규약의 게이트 위반 형식으로 차단하고 멈춘다. 사용자가 `게이트 생략 후 진행`이라고 명시하면 통과시키되 산출물에 생략 사실을 기록한다.

## 2. 절차

### 2-1. 요구사항 읽기

`requirements.md`를 읽어 기능·비기능 요구사항과 수용 기준을 파악한다. **요구사항에 없는 것을 계획에 넣지 않는다.** 필요하다고 판단되면 요구사항 갱신을 먼저 제안한다.

### 2-2. WBS 분해

각 요구사항을 **완료를 눈으로 확인할 수 있는 작업 단위**로 쪼갠다.

- 판정 불가한 항목(`개선`, `정리`, `최적화`)을 두지 않는다. 무엇이 되면 끝인지 적는다.
- 선행 관계를 명시한다. 병렬 가능한 것과 직렬인 것을 구분한다.
- 요구사항 ↔ WBS가 빠짐없이 대응되는지 확인한다. 덮지 못한 요구사항이 있으면 그것을 보고한다.

### 2-3. 일정

단계별 시작·종료를 잡되 **검증·리뷰 시간을 반드시 포함**한다. 구현만 계산한 일정은 계획이 아니다.

### 2-4. 리스크

각 리스크에 **트리거**(이 신호가 보이면 대응 개시)를 붙인다. 트리거 없는 리스크는 대응 시점을 놓친다.

### 2-5. Redmine 일감 매핑

RVS 2.0에서 WBS 항목과 Redmine 일감을 대응시킨다.

- 기존 일감은 **live 조회**해 subject·상태를 확인한다.
- 일감이 없는 WBS는 `미생성`으로 표시한다.
- **일감을 자동으로 만들지 않는다.** 생성이 필요하면 목록을 제안하고 사용자 승인을 받는다.

### 2-6. 작성 · 상태판 갱신

`templates/plan.md.tmpl`에서 출발한다. `overview.md` 상태판의 계획 행을 갱신한다.

## 3. 마무리

`status: draft`로 저장하고 보고한다.

```
plan.md 작성 완료 (status: draft)
  WBS N건 · 리스크 N건 · 미커버 요구사항 N건
  검토 후 승인하시면 /sdlc:design 로 진행합니다.
```

규약의 완료 보고 규격을 따른다 (RVS는 4블록).
