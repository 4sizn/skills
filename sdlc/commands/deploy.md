# /sdlc:deploy — SDLC 배포

`$ARGUMENTS`

## 0. 규약 로드

`sdlc-waterfall` 스킬을 Skill 도구로 로드한다.

## 1. 게이트

**둘 다 필요하다.**

| 조건 | 확인 |
|------|------|
| `test-plan.md` · `status: approved` | 무엇을 검증하기로 했는지 합의됨 |
| `test-runs/`에 PASS 결과 1건 이상 | 실제로 검증됨 |

추가로 **열린 blocker/critical 결함이 0건**이어야 한다. `defects/`를 확인한다. 있으면 목록과 함께 차단한다.

미통과 시 규약의 게이트 위반 형식으로 차단하고 멈춘다.

## 2. 절차

### 2-1. 포함 내용 확정

배포에 들어가는 Redmine 일감을 **live 조회**해 상태를 확인한다. 아직 Doing인 일감이 포함되어 있으면 사용자에게 알린다.

기준 브랜치와 배포 대상 커밋 사이의 실제 변경을 확인한다.

```bash
git log --oneline <기준>..<대상>
```

**계획에 없던 커밋이 섞여 있으면 보고한다.** 조용히 배포하지 않는다.

### 2-2. 체크리스트 실행

`templates/release.md.tmpl`의 체크리스트를 **실제로 실행**한다. 체크 표시만 채우지 않는다.

```bash
pnpm type:check && pnpm lint && pnpm format:check && pnpm build
```

형상 확인:

- 버전 번호가 갱신되었는가
- 배포 브랜치가 의도한 커밋을 가리키는가
- **`@rvs/common` 변경이 포함되면 그 레포가 먼저 반영·배포되었는가** — 순서가 뒤집히면 소비자가 없는 버전을 가리킨다
- 환경변수·설정 변경이 반영되었는가

### 2-3. 롤백 계획

> [!warning] 롤백 계획 없이 배포하지 않는다
> 판단 기준(어떤 신호가 보이면 롤백하는가), 절차, 소요 예상, 되돌릴 수 없는 변경 유무를 **배포 전에** 적는다. 사고가 난 뒤에 만드는 계획은 늦다.

### 2-4. MR·배포 실행

RVS 2.0에서 MR 생성은 `/git:create-mr`에 위임한다 (rvs-apps 세션). lefthook pre-push가 4종 게이트를 병렬 실행한다.

> [!warning] 실제 배포 실행은 사용자 승인 사항이다
> 이 커맨드는 준비·검증·기록을 담당한다. push·MR 머지·배포 트리거는 **사용자가 명시적으로 요청할 때만** 실행한다. 자의적으로 실행하지 않는다.

### 2-5. 배포 후 확인

주요 플로우 동작·에러 로그·성능 지표를 확인하고 결과를 기록한다. 확인하지 못했으면 그렇게 적는다.

## 3. 작성

`templates/release.md.tmpl`에서 출발해 `releases/<버전>.md`로 저장한다.

결과 섹션에는 **실제로 무슨 일이 있었는지** 적는다. 계획과 달랐던 점을 숨기지 않는다.

`overview.md` 상태판의 배포 행을 갱신한다.

## 4. Redmine 업데이트

포함된 일감의 상태 변경·Fixed Version 반영은 **초안만 만들고 사용자 승인 후** 실행한다.

## 5. 마무리

```
배포 준비 완료 — releases/<버전>.md
  포함 일감 N건 · 게이트 {PASS | FAIL}
  열린 blocker N건 · 롤백 계획 {작성됨 | 미작성}
  → 실제 배포 실행은 승인 후
```

규약의 완료 보고 규격을 따른다 (RVS는 4블록).
