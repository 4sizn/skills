SDLC 폭포수 동작 흐름

전역 sdlc-waterfall 규약과 9개 /sdlc:* 명령의 실행·승인·검증 흐름입니다. 프로젝트 로컬 규칙은 이 흐름을 대체하지 않고 구현 전 추가 게이트로 작동합니다.

산출물: <repo>/docs/sdlc/승인 상태는 사용자만 변경Hermes: external command adapter로 적용

1. 순차 라이프사이클

문서 작성 → 사용자 승인 → 다음 단계 진입. 구현 뒤에는 실제 검증과 별도 merge/deploy 승인까지 필요합니다.

2. 명령 진입 게이트

모든 명령은 먼저 대상 repo·git 상태·로컬 계약 문서를 확인합니다. 전제가 없으면 차단 사유를 보고하고 멈춥니다.

명령진입 조건통과 시
/sdlc:requirements없음overview.md + requirements.md 작성
/sdlc:planrequirements.md = approvedplan.md 작성
/sdlc:designplan.md = approveddesign.md 작성
/sdlc:implementdesign.md = approved + 프로젝트 로컬 착수 게이트implementation.md + 좁은 구현
/sdlc:testimplementation.md 존재test-plan.md / test-runs 기록
/sdlc:deploytest plan = approved + PASS 결과 1건 이상release 산출물 · 별도 사람 승인
/sdlc:review횡단 단계 · 없음reviews/<date>-<topic>.md
/sdlc:defect이슈 ID 필수재현 → 원인 → 수정 → 회귀
/sdlc:status없음읽기 전용 · 파일 정본으로 overview 보정

⛔ 미통과 시: 누락된 문서·실제 status를 정확히 보고하고, 사용자 승인 또는 명시적 게이트 생략 후 진행 지시를 기다립니다.

운영 불변식

  1. 새 단계 문서는 항상 draft로 시작한다.
  2. approved 전환은 사용자 명시 승인 후에만 가능하다.
  3. SDLC 승인만으로 코드를 수정할 수 없다. 로컬 게이트가 추가로 필요하다.
  4. agent는 자동 commit·push·merge·deploy 하지 않는다.
